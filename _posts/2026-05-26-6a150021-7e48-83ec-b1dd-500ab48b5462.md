# SciCore-Mol｜以分子认知模块增强大语言模型

# 00. 引言：这篇论文想解决什么

这篇论文讨论的是一个越来越核心的问题：大语言模型（large language model，大语言模型）能否真正理解分子、反应和药物设计任务。现有化学大模型大多把分子压缩成简化分子线性输入规范（SMILES）或自引用嵌入字符串（SELFIES），然后交给语言模型处理。这样做工程上方便，但代价很明显：分子本质上是图结构、三维构象和连续物理化学属性的组合，线性字符串只能间接表达这些信息，模型容易学到表面共现规律，而不是可靠的结构—性质关系。论文明确把这一问题称为离散语言符号与分子拓扑、连续反应数据之间的根本鸿沟。〔引用待核〕

SciCore-Mol 的核心思路是：不再把分子编码器、分子生成器、反应预测器当作外部黑箱工具，而是把它们作为“可插拔分子认知模块”接入大语言模型的隐藏状态空间。论文提出三个模块：拓扑感知模块、分子生成模块、反应感知模块，分别负责三维结构理解、潜空间扩散生成、反应级推理。它们通过学习到的表示接口与 8B 规模大语言模型骨干交互，而不是把所有结果压缩成自然语言反馈。〔引用待核〕

全文主线可以概括为：作者试图把化学任务从“文本化分子 + 通用语言推理”的路线，推进到“语言模型调度 + 专用结构模块计算 + 隐藏状态级融合”的路线。论文真正关心的不是单个任务刷榜，而是给科学大模型提供一种可扩展的架构模板。

# 01. 背景问题：为什么这件事难

## 1.1 分子不是普通文本，SMILES 只是压缩投影

分子性质往往取决于原子连接、芳香性、手性、构象、局部电荷分布、分子间相互作用等因素。SMILES 能表达连接关系，但它是线性序列，同一分子可以有多种 SMILES 写法，且三维构象、旋转等变性、局部空间邻近关系都需要模型从字符序列中间接恢复。

【背景知识：为什么 SMILES 对语言模型友好、对化学结构不够友好】

SMILES 的优势是可以被语言模型直接分词和训练；问题是它把分子图“摊平成一条字符串”。例如环闭合、支链、芳香性等信息都被编码成字符模式。语言模型可以学习这些模式，但很难天然知道两个在字符串上相距很远的原子在三维空间中可能相邻，也很难保证对分子旋转、平移等物理等价变换保持一致判断。论文因此强调，纯文本模型会在结构敏感任务上受到语义噪声和信息损失影响。〔引用待核〕

## 1.2 工具增强路线有效，但存在“文本回传瓶颈”

已有化学智能体常见做法是：大语言模型负责理解用户请求，然后调用外部工具，比如分子图编码器、反应预测器、数据库检索器、实验自动化平台。问题在于，工具计算出的结构嵌入、三维坐标、反应中间状态、计量信息，最后通常要转成文本再交还给大语言模型。这个接口太窄。

SciCore-Mol 的判断是：化学计算中最有价值的信息往往是稠密表示、连续数值和图结构关系，把这些信息转成自然语言，会引入不可逆的信息损失。因此作者把外部模块接到隐藏状态层，让模块输出可以被后续语言模型层直接注意到，这也是论文和普通工具调用系统的关键区别。〔引用待核〕

# 02. 方法核心：作者到底做了什么

## 2.1 总体架构：大语言模型负责调度，分子模块负责专业计算

SciCore-Mol 由一个大语言模型骨干和三个可插拔模块组成。论文使用 Qwen3-8B 作为基础骨干，完整系统约 8.6B 参数。推理时，模型根据任务上下文触发不同模块：遇到分子实体调用拓扑感知模块；遇到生成任务调用扩散生成模块；遇到反应任务调用反应感知模块。模块触发由预定义特殊标记控制。〔引用待核〕

这个设计解决的是任务异构性问题。分子性质预测、分子生成、反应产物预测、收率预测、分子描述生成，本质上需要不同类型的信息处理。把所有任务都压到同一个自回归文本解码器里，会让模型同时承担结构解析、连续生成、数值回归和自然语言输出，负担过重。SciCore-Mol 选择把这些能力拆成模块，再用大语言模型统一调度。

## 2.2 拓扑感知模块：用几何向量感知机把三维结构变成虚拟结构标记

输入是分子图和由 RDKit 生成的三维构象；输出是一个对接到大语言模型隐藏维度的分子结构向量。作者使用几何向量感知机（geometric vector perceptron，几何向量感知机）编码分子三维结构，整合原子序数、形式电荷、芳香性、环信息和三维坐标向量。经过四层消息传递后得到 256 维图级表示，再通过两层多层感知机映射到大语言模型隐藏维度 3072。〔引用待核〕

这个模块的关键直觉是：分子结构信息不应该只作为文本描述进入模型，而应该作为一个“虚拟结构标记”插入隐藏状态序列。这样后续自注意力可以直接访问三维几何信息。它解决的是 SMILES 难以显式表达几何不变性和空间关系的问题。

## 2.3 分子生成模块：用潜空间扩散替代直接 SMILES 自回归生成

输入是大语言模型隐藏状态中的任务语义；输出是分子潜变量，再由冻结的 SMILES 自编码器解码成分子。论文使用扩散变换器（diffusion transformer，扩散变换器）在连续分子潜空间中迭代去噪。潜变量形状为 127×64，来自预训练 SMILES 自编码器，生成模块训练时保持自编码器冻结。〔引用待核〕

传统语言模型直接生成 SMILES 时，一个字符错误就可能导致无效分子；扩散模型则在连续潜空间中逐步生成，更适合建模全局一致结构。论文还加入参考引导桥接初始化，用于保留源分子骨架的药物编辑任务；并使用无分类器引导增强文本条件控制。

## 2.4 反应感知模块：把反应拆成分子、角色、计量三类信号

输入是一组反应分子，每个分子带有结构嵌入、用量信息、功能角色和是否为目标的类型标记；输出可以是产物、缺失反应物或收率。作者构建了反应变换器（reaction transformer，反应变换器），每个反应标记由四部分组成：分子几何嵌入、标准化计量特征、角色嵌入、类型嵌入。〔引用待核〕

这个模块解决的是反应不是单分子性质预测的问题。反应推理需要知道哪个分子是反应物、试剂、溶剂、催化剂，以及用量关系。纯文本反应 SMILES 对这些角色和数量表达不稳定，而反应模块通过多通道编码显式建模这些因素。

# 03. 关键机制拆解：最值得理解的技术点

## 3.1 虚拟结构标记：把三维分子信息注入语言模型内部上下文

拓扑感知模块的核心公式可以写成：

\[
h_k^{mol}=W_2\mathrm{ReLU}(W_1h_{geo}+b_1)+b_2
\]

\[
\tilde{H}_X=\mathrm{Concat}(H_X,h_1^{mol},...,h_K^{mol})
\]

其中 \(h_{geo}\) 是几何向量感知机得到的分子结构表示，\(h_k^{mol}\) 是投影到语言模型隐藏空间后的分子向量，\(\tilde{H}_X\) 是拼接虚拟结构标记后的隐藏状态序列。〔引用待核〕

这组公式的作用很直接：让分子结构从“外部说明”变成“模型内部可注意对象”。传统做法可能把分子结构描述成“该分子含有芳香环和羧基”，但这种文本描述会丢掉精细拓扑和三维信息。虚拟结构标记则保留了几何编码器中的稠密信息，使后续 token 可以通过自注意力访问它。

这个机制引入的归纳偏置是：分子理解应该对三维结构敏感，并且对旋转、平移等几何变换保持合理一致性。论文使用的几何向量感知机在向量通道上不加偏置，以维持 SE(3) 等变性。这里的工程取舍是：它没有把每个原子都作为 token 接入大语言模型，而是通过全局池化形成图级结构标记，计算更轻，但可能损失细粒度原子级交互信息。

## 3.2 潜空间扩散生成：把分子生成从字符拼接转为连续去噪

扩散模块的核心公式包括：

\[
q(z_t|z_{t-1})=\mathcal{N}(\sqrt{1-\beta_t}z_{t-1},\beta_t I)
\]

\[
\hat{\epsilon}=\epsilon_{\theta}(z_t,t,c), \quad c=\mathrm{TextProj}(H_{LLM})
\]

\[
\hat{\epsilon}_{cfg}=\epsilon_{\theta}(z_t,t,\emptyset)+s(\epsilon_{\theta}(z_t,t,c)-\epsilon_{\theta}(z_t,t,\emptyset))
\]

第一式表示逐步加噪，第二式表示以大语言模型隐藏状态为条件预测噪声，第三式是无分类器引导，用于放大文本条件对生成结果的影响。〔引用待核〕

这个设计避免了自回归 SMILES 生成中的局部错误放大。直接生成字符串时，模型每一步只预测下一个 token，很容易出现括号、环编号、价态等错误；潜空间扩散是在连续空间中优化整体分子表示，再由冻结自编码器解码。它的优势是全局一致性更强，缺点是可解释性和精细结构约束依赖潜空间质量。

需要注意：论文结果显示 SciCore-Mol 在 DrugR 上平均主奖励为 0.2380，低于 GPT-4o 的 0.2545 和 GPT-5 的 0.2508，但高于 Qwen3-8B-Chem 的 0.2202；结构相似度方面为 0.5442，明显低于 Qwen3-8B 的 0.8795。也就是说，扩散模块提升了优化能力，但骨架保持仍有明显空间。〔引用待核〕

## 3.3 反应标记构造：让模型显式区分“分子是什么”和“分子在反应里做什么”

反应模块的核心表示为：

\[
r_j=f_{mol}(h_j^{geo})+f_{amt}(\bar{a}_j)+e_{role}(\rho_j)+e_{type}(\tau_j)
\]

其中 \(h_j^{geo}\) 表示第 \(j\) 个分子的几何嵌入，\(\bar{a}_j\) 是标准化计量信息和缺失掩码，\(\rho_j\) 是反应角色，\(\tau_j\) 区分观测分子与目标分子。〔引用待核〕

这个公式体现了反应建模中最重要的拆解：同一个分子作为反应物、溶剂、催化剂时语义完全不同；同样的反应物在不同当量、浓度或条件下也可能对应不同产物和收率。普通反应 SMILES 往往把这些信息混在字符串里，反应变换器把它们拆成结构、角色、数量三个通道。

该模块还用双头收率预测：一个连续回归头预测具体收率，一个粗粒度分类头作为正则项稳定回归。这个设计承认了收率预测的噪声很高，单纯回归容易不稳定，分类分支可以提供更粗的区间约束。

# 04. 实验验证：结果到底说明了什么

## 4.1 总体能力雷达图：证明模块化系统更均衡，但归一化结果需谨慎解读

论文把评测分为五类：化学知识、分子—文本翻译、分子生成、定量预测、合成推理。图 3 显示 SciCore-Mol 的整体能力较均衡，在开放模型中明显优于 Qwen3-8B、Qwen3-8B-Chem 和 LlaSMol-Mistral-7B；与 GPT-4o、GPT-5 相比，它在部分应用型化学任务上接近或超过闭源模型，但在通用化学知识维度仍弱于 GPT-5。〔引用待核〕

需要保留判断的是，雷达图分数来自最小—最大归一化，不是原始性能。不同指标、不同任务被聚合后，雷达图更适合看能力分布，不适合直接当作绝对胜负证据。

## 4.2 MoleculeNet 消融：GVP 确实带来结构敏感任务收益

表 1 比较了 Qwen3-8B、去掉监督微调和 GVP 的版本、去掉 GVP 的版本、完整 SciCore-Mol。完整模型在 Tox21 上 F1 从去 GVP 的 0.53 提升到 0.85，在 HIV 上从 0.70 提升到 0.94，在 QM9 上 MAE 从 0.90 降到 0.78。〔引用待核〕

这说明拓扑感知模块对结构敏感任务有实际贡献。尤其是毒性、活性和量子化学性质，通常与结构片段、三维构象和局部电子环境相关，纯文本模型不容易稳定捕捉。不过也要看到，BBBP 上完整模型 0.49 低于若干消融版本，FreeSolv 上 0.81 也不如 Qwen3-8B 的 0.72。模块收益不是无条件覆盖所有任务，任务数据规模、标签噪声、构象质量都会影响结果。

## 4.3 分子生成结果：扩散模块提升生成质量，但结构保持存在取舍

在 SMolInstruct 分子生成任务中，SciCore-Mol 的 RDK 指纹相似度达到 61.3%，有效率 93.7%；Qwen3-8B-Chem 为 44.5% 和 93.7%；GPT-4o 为 47.0% 和 85.0%。这说明扩散生成模块在文本条件分子生成上明显优于只做化学领域微调的语言模型。〔引用待核〕

但在 DrugR 药物优化任务中，SciCore-Mol 的平均主奖励高于 Qwen3-8B-Chem，结构相似度却低于 Qwen3-8B。这反映出一个常见生成优化矛盾：为了提高目标属性，模型可能偏离原始骨架；为了保骨架，又可能牺牲优化空间。论文也指出，编辑型场景可能需要更强的结构保持引导策略。〔引用待核〕

## 4.4 合成与反应任务：反应模块改善部分反应能力，但结果并非全面领先

SMolInstruct 合成任务中，SciCore-Mol 的正向合成 RDK-FTS 为 70.0%，有效率 97.7%；逆合成 RDK-FTS 为 63.7%，有效率 99.3%，均优于 Qwen3-8B-Chem 和闭源模型。〔引用待核〕

ChemBench4K 中，SciCore-Mol 平均准确率 71.05%，接近 GPT-4o 的 70.25%，低于 GPT-5 的 75.72；在逆合成上达到 80.67%，高于 GPT-5 的 78.00，但在收率预测上 38.67，低于 GPT-4o 的 45.66 和 GPT-5 的 43.00。〔引用待核〕

ORD 结果更复杂。完整 SciCore-Mol 在产物+收率预测有效率上达到 97.6%，远高于去反应模块的 11.51%，说明反应模块对结构化输出有效性非常关键。但单独产物预测有效率 42.0%，低于 GPT-5 的 82.0 和 LlaSMol-Mistral-7B 的 83.0；反应物预测有效率 74.7%，低于 GPT-4o 和 GPT-5。论文中“反应级推理需要专门架构支持”的结论有消融依据，但“全面优于闭源模型”不能从 ORD 表格直接推出。〔引用待核〕

## 4.5 案例分析：展示了模块触发路径，但证据强度低于系统性评测

表 3 展示了三个案例：分子生成、产物与收率预测、分子描述生成。SciCore-Mol 在 tankyrase 抑制剂样分子生成中保持了 thiopyranopyrimidine 核心和对三氟甲基苯基取代模式；在偶联反应中恢复了正确耦合产物并预测 57.60% 收率；在芳香氨基甲酸酯描述中识别出 carbamate motif。〔引用待核〕

这些案例有解释价值，说明三个模块在真实开放式提示中能被调度起来。但案例数量少，不能替代系统评测。更强的证据仍来自消融表和多任务 benchmark。

# 05. 这项工作的真正价值

SciCore-Mol 的价值主要在架构范式，而不是某一个指标。它把化学大语言模型从“分子字符串任务统一化”推进到“语言模型作为协调中心、专用化学模块作为内部认知部件”的方向。

它改变的认知是：科学大模型未必只能靠扩大语言模型规模获得专业能力。对于分子这种结构强、几何强、数值强的对象，引入合适的归纳偏置可能比单纯扩大参数更有效。论文中 8B 级系统在若干化学应用任务上接近或超过闭源大模型，支持了这一点。〔引用待核〕

它对后续研究的启发包括三点：第一，分子编码器可以作为隐藏状态插件，而不是只做外部工具；第二，生成模型可以通过大语言模型隐藏语义进行条件控制，而不是只靠文本 prompt；第三，反应建模需要显式角色和计量通道，不能只依赖反应 SMILES。

从应用角度看，这项工作最可能影响多任务药物设计助手、反应规划系统、分子性质解释系统和化学智能体。它解决的重点是范式变化，同时带来一定性能收益；“更准”和“更快”不是它唯一重点。

# 06. 局限与需要验证的点

1. **三维构象依赖 RDKit 生成**：拓扑模块的输入构象质量会影响性能，论文未充分讨论构象不确定性、多构象集合和低质量构象对下游任务的影响。〔引用待核〕

2. **生成模块结构保持不足**：DrugR 结果显示 SciCore-Mol 的结构相似度不高，说明当前潜空间扩散更偏属性优化，编辑型药物设计还需要更强 scaffold-preserving 机制。〔引用待核〕

3. **反应能力并非全面领先**：ORD 表格显示反应模块提升消融版本很明显，但完整模型在若干反应指标上仍低于 GPT-5 或 GPT-4o，尤其是产物预测和反应物预测。〔引用待核〕

4. **训练管线复杂**：组件预训练、跨模态对齐、联合多任务训练、任务特定微调构成三阶段流程，工程成本高，模块间误差传播和训练稳定性需要更多报告。〔引用待核〕

5. **扩展边界未充分验证**：论文明确系统主要面向小分子，尚不支持蛋白质等更大实体；聚合物、晶体、多分子复合物等方向只是作者提出的潜在扩展。〔引用待核〕

# 07. 总结与延伸探讨

总体评价：SciCore-Mol 最值得关注的地方，是把分子结构编码、潜空间生成、反应级建模从“外部工具”升级成大语言模型内部可调度、可对齐、可联合训练的认知模块。

最值得记住的点是“隐藏状态级接口”。这比文本工具调用更适合化学，因为化学对象的核心信息往往不是一句自然语言能完整表达的，而是拓扑、几何、连续潜变量和计量关系。SciCore-Mol 用虚拟结构标记、扩散条件生成和反应多通道标记分别处理这三类信息。

下一步最值得推进的方向有两个：一是把分子生成模块做成更强的结构保持编辑器，尤其适配 scaffold hopping、片段替换、口袋条件生成和合成可达性约束；二是让反应模块进一步接入真实实验条件、机理路径和不确定性估计，否则收率预测仍难满足精密化学决策需求。
